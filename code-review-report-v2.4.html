⚠️ 问题与建议

🟢 撤销后跨页面课时刷新依赖手动 reload 一致性

ScheduleProvider.undoCheckIn 直接写 courses 表，但不通知 CourseProvider； 详情页已手动 context.read<CourseProvider>().loadCourses() 兜底。该行为与既有 checkIn 一致（checkIn 也未刷新课程）， 属现有架构惯例。若未来课时屏与详情页同栈常驻，建议统一由事件/监听刷新。

🟢 课时取值为 double 但 UI 限定整数 建模

Schedule.courseHours 用 double 存储（与 Course 体系一致），UI 步进器为整数（min 1）。 当前兼容历史/手动 0.5 类数据无碍；若后续永不支持小数，可考虑在 UI 文案明确「整数课时」。无需立即处理。

🟢 24h 边界判定使用严格大于 边界

difference(checkInTime) > Duration(hours: 24) 表示「恰好 24:00:00 仍可撤销」。语义合理，已有 25h 拒绝用例覆盖； 如需更严可改为 >=，属产品口径选择。
